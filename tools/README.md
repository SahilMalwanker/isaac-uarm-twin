# Reproducing the Artwork

The primary images use actual, hash-verified public uArm meshes, a depth buffer, interpolated surface normals, directional lighting, cast shadows and supersampled raster output. Every non-uArm object is original procedural geometry. No plant CAD or real photographs are used.

```bash
python -m pip install -r requirements-art.txt
python tools/fetch_swiftpro_meshes.py
python tools/render_readme.py --meshes assets/swiftpro/meshes --cell --frames 120
```

This is an offline Python software renderer, not an Isaac Sim screenshot exporter. It does not launch the simulator, a browser, JavaScript or project executables. Animation poses come from the waypoint model; hand-offs and timing are illustrative, not physics measurements. Rendering 120 frames can take several minutes on a CPU. Omit `--frames` to regenerate only stills.

| Output | Purpose |
| :--- | :--- |
| `hero-dark.png`, `hero-light.png` | GitHub-compatible 2400 × 760 hero banners (dark and light themes) |
| `twin-viewport.png` | 2400 × 1500 annotated 3D viewport still of the cell |
| `linkage.png` | 2400 × 1260 annotated 3D uArm Swift Pro linkage and PhysX constraint diagram |
| `twin-cycle.gif` | 120-frame animated 3D replay at 1280 × 800 |
| `calibration-dark.svg`, `calibration-light.svg` | Two-point servo calibration and 60 Hz smoothing response charts |
| `architecture.svg` | Vector architecture diagram (generated by `make_readme_art.py`) |

The renderer refuses meshes whose SHA-256 does not match the pinned upstream file. It builds a rendering-only simplified mesh in memory; no source mesh is altered or redistributed. The CPU implementation uses orthographic projection and simplified lighting, not physically based path tracing.

`make_readme_art.py` owns the waypoint replay and engineering schematic helpers. Its low-detail diagnostic outputs belong under ignored `tools/previews/`; they are not the primary README renders. `architecture.svg` remains a crisp vector explanation.

```bash
python tools/build_scene.py --check
python -m pytest tests/test_render_readme.py
```

The presentation equipment has bevels, rollers and mounting details that are intentionally absent from the simulation's simpler collision model. Do not use the images to infer collision clearance or validate real hardware motion.
