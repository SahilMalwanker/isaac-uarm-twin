# Building the Twin

## Assets

`scene/cell.usda` is generated by `tools/build_scene.py`. It is Z-up, uses metres and specifies gravity of 9.81 m/s squared. Table, belt bodies, sensors, parts, camera, lights and embedded graph scripts are authored from scratch. No original plant USD is referenced.

Fetch the separately licensed uArm meshes first:

```bash
python tools/fetch_swiftpro_meshes.py
python tools/build_scene.py
```

The downloader checks every file against its pinned upstream hash. Files remain ignored under `assets/swiftpro/meshes/`.

## Robot Import

In Isaac Sim 5.x, enable the URDF importer, physics and OmniGraph ScriptNode extensions. Import these models individually with a fixed base and preserved link/joint names:

| Input | Required output reference |
| :--- | :--- |
| `assets/swiftpro/swiftpro_twin.urdf` | `scene/robot/swiftpro_twin/swiftpro_twin.usd` |
| `assets/swiftpro/swiftpro_twin_gripper.urdf` | `scene/robot/swiftpro_twin_gripper/swiftpro_twin_gripper.usd` |

The URDFs already include inertias and simplified collision geometry. Inspect the importer settings rather than automatically regenerating inertias or collapsing linkage links. The importer creates an open articulation tree; the next step restores the closed loops.

Open each imported robot USD, run `isaac/tools/rig_swiftpro.py` in the Script Editor, and save the stage. The script locates the robot's default prim, applies the drive parameters, removes passive drives, adds the three loop constraints and authors the tool reference point. It can also operate on the assembled cell's `/World/uarm*/swiftpro` prims.

Open `scene/cell.usda`. The three references must compose to:

```text
/World/uarm1/swiftpro
/World/uarm2/swiftpro
/World/uarm3/swiftpro
```

The follower currently looks for each articulation at `/World/uarmN/swiftpro/Base`. Importer versions may place the articulation root on a fixed joint instead. Verify the actual root in your stage and update `arm_config()` in `isaac/follower.py` if necessary. Also verify `Joint1`, `Joint2`, `Joint6` and arm 2's `JointGripperExt` names.

## First Simulation

1. Open the cell without connecting physical robots. Check missing references, units, gravity and collider placement.
2. Press Play with the follower disabled. Confirm stable fixed bases and closed loops; inspect any PhysX warnings.
3. Apply small individual drive targets and confirm axes and limits before testing large excursions.
4. Check that the holder rests on each belt and that S1/S2 and S3/S4 start and stop their respective belts.
5. Use the graph's tool toggles to test pickup/release. Do not infer tool state from servo telemetry: it is not present in that payload.
6. Load `isaac/follower.py` only after local articulation behaviour is stable, then introduce telemetry from the hardware controller.

The new public reconstruction has not been opened or run in Isaac Sim during preparation. These are acceptance steps still to perform, not completed validation results. The README artwork has a separate, more detailed rendering model and cannot verify this stage.
